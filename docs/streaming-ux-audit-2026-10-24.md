# Streaming viewer UX audit — 24 October 2026

Scope: welcome, email/Google/Apple entry, verification, home and series navigation, episode selection, purchase, wallet, playback, recently watched, saved items, profile, and the legacy `/old` route. I inspected the current frontend and backend, exercised public API routes, and used Chromium at 390×844 and 1440×900 with a mocked signed-in session to inspect the authenticated screens. This is a UX and readiness review, not a successful end-to-end payment certification.

## Resolve before a client demo of the paid journey

1. **Replace the sample videos and verify rights/hosting.** The live public catalog returns eight episodes for each of the two home series; all 16 report the same public YouTube ID, `aqz-KE-bpKQ` (the seed's Big Buck Bunny sample). Fourteen are marked premium. The catalog response itself exposes `youtubeId`, so these sample videos cannot be meaningfully paywalled outside the app. Use licensed final cuts and signed streaming for premium releases. Evidence: `backend/src/data/data.service.ts` (`seedHomeSeries`), `backend/src/content/content.service.ts` (`viewerSeries`), live `GET /api/content/viewer-series/{slug}`.
2. **Settle the offer and finish its route back to playback.** The purchase sheet quotes an episode in credits; insufficient balance sends the viewer to `/wallet`. Wallet back goes to `/`, not the selected episode, and the original stage/selection is not restored by that path. The cheapest active INR pack is ₹50; there are zero active bundles. The current ₹100 pack grants 110 credits, which is different from the requested named ₹100/20-episode offer. Define whether the client wants a specific 20-episode bundle, a 20-unlock pass, or credits, then show the rupee total and entitlement terms before taking payment. Evidence: `EpisodePurchaseSheet.tsx`, `WalletApp.tsx`, `DesertParallax.tsx`; live DB counts: 0 active packages, 9 active wallet packs.
3. **Fix visible dead ends in onboarding.** “Continue with Apple” has no click handler. Terms and Privacy links both return 404. A password-reset backend exists, but there is no “Forgot password?” or reset screen in the viewer UI. Evidence: `AuthOptions.tsx`, `AuthForm.tsx`, frontend route list, backend `auth.controller.ts`; local HTTP checks returned 404 for `/terms` and `/privacy`.
4. **Verify actual Google and payment completion with test accounts.** The API health check and database now pass, the migration status is current, and Google OAuth start redirects to Google. This does not prove the provider callback, email delivery, Razorpay/Stripe confirmation, webhook, refunds, or purchased playback. Run real test-mode journeys on mobile and desktop before promising readiness. Earlier notes that the database is still unreachable are stale.

## Next UX fixes

5. **Make saved and recently watched truly account-based.** The home Save button only flips component state and has no Saved destination; it resets on reload. Home “Recently watched” is localStorage per device, and an episode counts as watched as soon as its player is closed, regardless of progress. The backend has watchlist and watch events, and `/old` has a library, but the default `/` experience does not expose a persistent saved/watch-history flow. Evidence: `DesertParallax.tsx`, `StreamingApp.tsx`, backend `content.service.ts`.
6. **Provide a purchase-help path.** Wallet history shows transactions and access expiry, but there is no receipt/detail view, support destination, or in-app route to resolve a charge that stays pending. The sheet tells viewers to “Contact support” without a link. Evidence: `WalletApp.tsx`, `EpisodePurchaseSheet.tsx`.
7. **Improve failed-data states.** Wallet pack and region fetch errors are swallowed, leaving skeletons or an unclear gateway state. The home page deliberately renders fallback episode cards when its catalog request fails; selecting them then produces an error. Show a clear unavailable/retry state rather than a purchasable-looking card. Evidence: `WalletApp.tsx`, `DesertParallax.tsx`, `HomeEpisodeAccess.tsx`.
8. **Fix the desktop featured-card crop.** At 1440×900 the card beside the details uses artwork positioned for a wider composition; the printed series title is clipped and the subject is mostly outside the card. Use a portrait-specific crop or art direction. The first scroll did reach the episode view without over-scrolling in the Chromium check. Evidence: desktop browser review, `DesertParallax.tsx` and `GyroSeries.tsx`.
9. **Unify player behavior across video sources.** YouTube uses custom overlay controls around an embed; Cloudflare playback uses an iframe without the same controls. Validate captions, error recovery, full-screen, focus return, and playback at narrow/landscape sizes for both sources. Evidence: `EpisodeExpansion.tsx`.
10. **Expose account controls.** The profile offers navigation and log out, but no name edit, password change/reset entry, account deletion, or purchase-access library. Backend profile and password-reset operations exist; prioritize the controls that are required for launch and support. Evidence: `profile/page.tsx`, backend auth routes.

## Content and presentation polish

- The default page metadata still says “Streamline” and “A streaming platform for movies and shows,” while the viewer UI says RVNext Gen (`src/app/layout.tsx`).
- Home episode cards use alternating series artwork, not episode-specific imagery or titles; until final assets are supplied, the rows suggest distinct videos that are not there (`DesertParallax.tsx`).
- Some essential information is 10–12px and low-contrast, particularly the profile, desktop card eyebrow, purchase terms, and wallet metadata. Review on real phones and at enlarged text settings (`profile/page.tsx`, `DesertParallax.tsx`, `EpisodePurchaseSheet.tsx`, `WalletApp.tsx`).
- `docs/episode-payments.md` describes direct per-episode gateway checkout and an unreachable database; current UI uses wallet credits for individual episodes, and the DB is reachable. Update the handoff note before using it with the client.

- Backend TypeScript check passed; 16 Jest suites / 87 tests passed. Prisma reported 25 migrations and an up-to-date schema. API health returned 200 with `db: up`.
- Public home-series responses returned 200 with eight playable records each; both auth legal links returned 404; Google OAuth start returned a 302 to Google.
- Chromium screenshots and stage navigation covered mobile and desktop login options, home, profile, wallet shell, desktop episode view, and a mocked insufficient-credit purchase sheet. The test session and 403 purchase gate were mocked, so they do not certify real sign-in or charging.
